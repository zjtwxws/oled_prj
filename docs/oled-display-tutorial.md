## 一、从一个像素开始

### 1.1 像素的本质

所有显示系统的最小单位都是像素（Pixel）。对于 SSD1306 这种单色 OLED：

- 每个像素只有两种状态：亮（白）或灭（黑）
- 用一个 bit 表示：1 = 亮，0 = 灭

`ssd1306.h` 中定义的颜色常量：

```c
#define SSD1306_COLOR_BLACK  0  /* 像素灭 */
#define SSD1306_COLOR_WHITE  1  /* 像素亮 */
```

### 1.2 最底层的绘点函数

设置一个像素，本质上是修改显存缓冲区中对应 bit 的值：

```c
void ssd1306_draw_pixel(uint8_t x, uint8_t y, uint8_t color)
{
    if (x >= SSD1306_WIDTH || y >= SSD1306_HEIGHT) return;
    uint8_t page = y / 8;
    uint8_t bit  = y % 8;
    if (color)
        buffer[page * SSD1306_WIDTH + x] |= (1 << bit);
    else
        buffer[page * SSD1306_WIDTH + x] &= ~(1 << bit);
}
```

关键理解：
- (x, y) 是屏幕坐标，x 从 0 到 127（列），y 从 0 到 63（行）
- y/8 确定像素属于第几个 page，每 8 个垂直像素打包成一个字节
- y%8 确定像素在字节内的第几个 bit
- |= 或 &=~ 只修改目标 bit，不影响同字节的其他 7 个像素

通用原理：任何显示设备，无论分辨率、色深、接口如何，底层都是修改某块内存中代表像素的数据。

## 二、从像素到屏幕：显存映射

### 2.1 SSD1306 的显存组织

SSD1306 内部有一块 GDDRAM（Graphic Display Data RAM），容量为 128x64 bits = 1024 bytes。
内存地址公式：offset = page * 128 + column

### 2.2 本项目中的显存缓冲区

```c
static uint8_t buffer[SSD1306_WIDTH * SSD1306_PAGES];  // 128 * 8 = 1024 bytes
```

这是一块在 MCU 内存中的镜像。所有绘图操作都在这里完成，然后通过 `ssd1306_update_screen()` 一次性发送到 OLED。

为什么需要镜像缓冲区？

- 批量更新：逐点修改 GDDRAM 效率极低，修改本地缓冲区后再整页发送快得多
- 原子操作：可以在内存中完整构图后再一次性展示，避免显示撕裂
- 特效支持：滚动、淡入淡出等效果直接在内存中运算

### 2.3 帧缓冲模式

在远程模式下，项目使用了两级缓冲：PC 渲染 -> UART 传输 -> STM32 frame_buf 拼装 -> buffer 复制 -> I2C 发送 -> SSD1306 GDDRAM

每一级的隔离使得渲染和传输可以异步进行。

## 三、SSD1306 控制器：把数据变成光

### 3.1 芯片角色

SSD1306 是 OLED 面板的驱动控制器。它负责：

1. 接收 MCU 发来的命令和数据（通过 I2C 或 SPI）
2. 管理 GDDRAM（显存）
3. 根据 GDDRAM 内容驱动 OLED 面板的每个像素
4. 提供对比度控制、显示开关、硬件滚动等高级功能

### 3.2 命令 vs 数据

SSD1306 通过 I2C 的控制字节区分命令和数据：

| 控制字节 | 含义 |
|---------|------|
| 0x00 | 接下来的字节是命令 |
| 0x40 | 接下来的字节是数据 |

本项目中的实现：

```c
static void ssd1306_write_cmd(uint8_t cmd)
{
    i2c_drv_write_reg(SSD1306_I2C_ADDR, 0x00, &cmd, 1);
}
static void ssd1306_write_data(const uint8_t *data, uint16_t len)
{
    i2c_drv_write_reg(SSD1306_I2C_ADDR, 0x40, data, len);
}
```

### 3.3 关键命令解析

| 命令 | 字节 | 含义 |
|------|------|------|
| 0xAE / 0xAF | 1 | 显示关/开 |
| 0x81 + val | 2 | 设置对比度 (0~255) |
| 0x20 + mode | 2 | 寻址模式: 0=水平, 1=垂直, 2=页 |
| 0xA0 / 0xA1 | 1 | 段重映射 (左右镜像) |
| 0xC0 / 0xC8 | 1 | COM 扫描方向 (上下翻转) |
| 0xA4 / 0xA5 | 1 | 全屏点亮/恢复 GDDRAM 内容 |
| 0xA6 / 0xA7 | 1 | 正常/反相显示 |
| 0x26 / 0x27 | 6+ | 水平滚动 (左/右) |
| 0x8D + 0x14 | 2 | 启用电荷泵 (3.3V 供电必须) |

### 3.4 为什么 3.3V 供电需要电荷泵？

SSD1306 的核心逻辑只需 3.3V，但 OLED 面板驱动需要 7~15V。内置的电荷泵将 3.3V 升压到面板所需电压。如果不启用电荷泵（0x8D, 0x14），屏幕完全不亮。这是最常见的屏幕不亮原因之一。

### 3.5 寻址模式

本项目使用水平寻址模式（Horizontal Addressing Mode）：0x20, 0x00。在水平模式下，每次写入数据后列地址自动 +1，到达行末后页地址自动 +1。这允许用一次连续 I2C 传输发送整页 128 字节数据，效率最高。

## 四、初始化序列：屏幕的开机自检

### 4.1 完整的初始化命令序列

SSD1306 上电后必须按特定顺序初始化，本项目经验证的序列如下：

```c
static const uint8_t ssd1306_init_cmds[] = {
    0xAE,           // [1] 关闭显示（初始化期间不亮，避免花屏）
    0x20, 0x00,     // [2] 寻址模式：水平
    0x40,           // [3] 起始行 = 0
    0xA0,           // [4] 段重映射：正常方向
    0xC0,           // [5] COM 扫描：正常方向
    0xA8, 0x3F,     // [6] MUX 比率 = 64 (128x64 屏)
    0xD3, 0x00,     // [7] 显示偏移 = 0
    0xD5, 0xF0,     // [8] 振荡频率 + 分频
    0xD9, 0x22,     // [9] 预充电周期
    0xDA, 0x12,     // [10] COM 引脚硬件配置
    0xDB, 0x20,     // [11] VCOMH 电压
    0x81, 0xFF,     // [12] 对比度 = 255 (最大)
    0xA4,           // [13] 恢复 GDDRAM 内容显示
    0xA6,           // [14] 正常显示（不反相）
    0x8D, 0x14,     // [15] 启用电荷泵
    0x2E,           // [16] 停用滚动
    0xAF            // [17] 打开显示
};
```

### 4.2 为什么要延时 100ms？

SSD1306 手册要求 VDD 稳定后至少等待 3us。但实际电路中电源上升可能缓慢，复位电容充电也需要时间。厂家示例用 100ms 给了足够余量。

### 4.3 初始化后的清屏

初始化的最后一步要确保 OLED 显示全黑：因为在显示关闭期间 GDDRAM 可能包含随机数据，直接打开会花屏。

## 五、I2C 通信：MCU 如何对话屏幕

### 5.1 物理连接

I2C 只需要 2 根线（SCL 时钟 + SDA 数据），加上电源和地共 4 根线。本项目使用 STM32F407 的 I2C2（PB10=SCL, PB11=SDA），Fast Mode 400kHz。

### 5.2 从机地址

SSD1306 的 7 位 I2C 地址是 0x3C（SA0 引脚接低电平）。如果 SA0 接高电平则为 0x3D。STM32 HAL 库会自动左移 1 位，所以 HAL 函数中的 address 参数需要 0x3C << 1 = 0x78。

本项目 i2c_drv.c 中做了封装：

```c
HAL_I2C_Mem_Write(p_i2c, (uint16_t)(dev_addr << 1),
    (uint16_t)reg, I2C_MEMADD_SIZE_8BIT,
    (uint8_t *)data, len, I2C_TIMEOUT_DEFAULT);
```

### 5.3 速度与效率

SSD1306 支持 I2C Fast Mode (400kHz)。整屏刷新 8 pages 约需 21ms，最大刷新率约 47fps。加上 MCU 渲染时间，实际约 25fps。

### 5.4 超时保护

I2C 总线可能因干扰、接触不良等原因挂死（SDA 被从机拉低不放）。本项目使用 100ms 超时而非 HAL_MAX_DELAY，避免 MCU 永久阻塞。

## 六、字库系统：从字符编码到点阵

### 6.1 字模的本质

字模就是一个二维的点阵数组。本项目使用：
- ASCII: 8x16 像素，每个字符 16 字节
- 中文 (GB2312): 16x16 像素，每个汉字 32 字节

### 6.2 ASCII 字模存储格式

以字符 ! 为例，每字节代表一列 8 个垂直像素，bit0 在顶部。总共 16 字节 = 8 列 x 2 pages。

```c
/* 0x21 ! */
{0x00,0x00,0x00,0xF8,0x00,0x00,0x00,0x00,   // page0 (上半)
 0x00,0x00,0x00,0x33,0x30,0x00,0x00,0x00},  // page1 (下半)
```

### 6.3 中文字模编码

中文使用 GB2312 区位码映射到 Flash 中的字模偏移：
GB2312 内码 = 0xA1A1 + (区号-1)*94 + (位号-1)
字模偏移 = ((区号-16)*94 + (位号-1)) * 32
跳过 1~15 区（非汉字内容），每个汉字 32 字节。

### 6.4 UTF-8 解码

本项目字符串使用 UTF-8 编码，需要在渲染时识别中文字符：0x00~0x7F 为单字节 ASCII，0xE0~0xEF 为 3 字节中文。

### 6.5 绘制中文字符的具体过程

一个 16x16 的汉字占 2 pages 高。glyph[c*2] 和 glyph[c*2+1] 分别对应第 c 列的上半部分和下半部分。

```c
static void draw_chinese_char(uint8_t x, uint8_t page, const uint8_t *glyph)
{
    uint8_t *buf = ssd1306_get_buffer();
    for (uint8_t c = 0; c < FONT_CHINESE_W; c++, x++) {
        buf[page     * SSD1306_WIDTH + x] = glyph[c * 2];
        buf[(page + 1) * SSD1306_WIDTH + x] = glyph[c * 2 + 1];
    }
}
```

## 七、显示管理器：从绘点到应用层抽象

### 7.1 分层架构

| 层级 | 模块 | 职责 |
|------|------|------|
| HAL 层 | STM32 HAL | 封装寄存器操作 |
| 硬件驱动层 | ssd1306, i2c_drv, key_drv, uart_drv | 封装具体外设 |
| 中间件层 | protocol, font | 协议解析、字库管理 |
| 应用模块层 | display_mgr, menu_mgr, led_mgr | 业务逻辑 |
| 应用入口层 | user_app | 主循环编排 |

### 7.2 display_mgr 的核心职责

display_mgr 是显示系统的总调度器，管理：

1. 模式切换：本地模式（STM32 自渲染）<-> 远程模式（PC 渲染）
2. 文字管理：content_text（当前显示文字）+ boot_text（上电默认文字）
3. 特效调度：7 种特效的选择、参数管理和逐帧更新
4. 时间/天气数据存储：接收 PC 下发的时间天气信息
5. 远程帧缓冲：接收 PC 分段帧、拼装、刷屏

### 7.3 全屏文字渲染

draw_text_fullscreen() 体现了嵌入式文本渲染的核心逻辑：
1. 区分中英文宽度（16px vs 8px）
2. 超过行宽自动换行（col=0, page+=2）
3. 超过屏幕高度停止（page >= 6 即 y >= 48）

## 八、显示特效原理

### 8.1 滚动特效

所有滚动特效的本质都是在 buffer 中 memmove 像素数据。以左滚为例：

```c
static void effect_scroll_left(void)
{
    uint8_t *buf = ssd1306_get_buffer();
    for (uint8_t p = 0; p < SSD1306_PAGES; p++) {
        uint8_t *line = &buf[p * SSD1306_WIDTH];
        memmove(line, line + SCROLL_STEP_PX, SSD1306_WIDTH - SCROLL_STEP_PX);
        memset(line + SSD1306_WIDTH - SCROLL_STEP_PX, 0, SCROLL_STEP_PX);
    }
}
```

每一帧将每页数据向左移动 SCROLL_STEP_PX（2px），右侧补 0。连续播放产生平滑滚动效果。

滚动方向速查：
| 方向 | 操作 |
|------|------|
| 左滚 | memmove(line, line+step, width-step) + 右侧清零 |
| 右滚 | memmove(line+step, line, width-step) + 左侧清零 |
| 上滚 | memcpy(page[n], page[n+1], width) + 末页清零 |
| 下滚 | memcpy(page[n], page[n-1], width) + 首页清零 |

SSD1306 内置硬件滚动功能，但本项目未使用，原因是：软件滚动更灵活（可控制步长、可与其他特效组合），且 168MHz Cortex-M4 做 memmove 毫无压力。

### 8.2 翻页特效

每隔 3 秒切换一次：显示文字 -> 空白 -> 显示文字 -> 空白。实现极简：flip_phase 异或翻转后重绘。

### 8.3 淡入淡出特效

利用 SSD1306 的对比度寄存器（0x81）实现渐变：32 步，每步 30ms，完整渐变约 1 秒。对比度 0->255 是淡入，255->0 是淡出。

这是单色屏实现灰度效果的常用技巧——不是真正的灰度，而是整体亮度的渐变。

## 九、双模式架构：本地渲染 vs 远程帧缓冲

### 9.1 架构概览

本地模式（PC 断开）: STM32 -> 文字+特效渲染 -> buffer[] -> I2C -> OLED
远程模式（PC 连接）: PC GDI 渲染 -> 帧缓冲 -> 协议分段 -> UART -> STM32 frame_buf[] 拼装 -> buffer[] -> I2C -> OLED

### 9.2 远程帧缓冲传输

1024 字节的帧缓冲拆分成 6 段通过 UART 传输，每段 payload <= 200 字节。115200 波特率下，每段约 17ms。

首段 (seg=0) 清空帧缓冲，末段收齐后 memcpy 到 OLED buffer 并刷屏。

### 9.3 菜单激活期间的刷屏抑制

远程模式下菜单激活时，帧缓冲继续在后台拼装，但不直接刷屏——防止菜单渲染和远程帧刷屏冲突。菜单退出时一次性刷出最近完整帧。

## 十、菜单系统的显示层设计

### 10.1 菜单布局

128x64 OLED 分 4 行 x 16px，利用 page 级对齐。选中行反白（白底黑字），普通行缩进 16px 正常显示。

### 10.2 反白渲染技术

反白不是调用硬件反相命令（0xA7），而是直接在 buffer 中操作：先将整行所有 bit 置 1（白色背景），再以擦除模式绘制文字（&= ~glyph）。这样只反白一行，不影响其他行。

### 10.3 文本超宽截断

当菜单项文本过长、超出屏幕宽度时，自动右对齐截断：文本最右端贴齐后缀（如 [x]、[128]）左边，左侧超出部分自然截断。

### 10.4 滚动指示器

当子菜单超过 4 项，最后一行显示省略号提示。滚到底时该项消失，最后一项正常显示。

## 十一、扩展到所有屏幕：通用开发方法论

> 以上以 SSD1306 128x64 OLED 为例拆解了整个显示栈。下面将这些经验抽象为适用于任何类型屏幕的开发方法论。

### 11.1 显示系统开发的通用分层模型

无论你面对的是 0.96 英寸 OLED 还是 7 英寸 TFT-LCD，显示系统都遵循相同的分层：

| 层级 | 内容 |
|------|------|
| Layer 5: UI 框架 | 菜单、控件、窗口管理、事件分发 |
| Layer 4: 图形库 | 文本渲染、图形绘制、特效、双缓冲 |
| Layer 3: 显示驱动抽象 | 帧缓冲管理、区域刷新、旋转/镜像 |
| Layer 2: 控制器驱动 | 初始化序列、寄存器读写、GDDRAM 操作 |
| Layer 1: 通信接口驱动 | I2C / SPI / 8080 并行 / MIPI DSI / LVDS |
| Layer 0: 硬件 | MCU/MPU + 屏幕模组 |

### 11.2 各类屏幕对比

| 类型 | 代表型号 | 接口 | 分辨率 | 色深 | 典型应用 |
|------|---------|------|--------|------|---------|
| 单色 OLED | SSD1306 | I2C/SPI | 128x64 | 1bit | 穿戴、仪表 |
| 单色 LCD | ST7567 | SPI/8080 | 128x64 | 1bit | 工控 |
| 彩色 TFT | ILI9341 | SPI/8080 | 320x240 | 16bit | 嵌入式 GUI |
| 彩色 IPS | ST7789 | SPI | 240x240 | 16bit | 智能手表 |
| MIPI DSI | -- | MIPI | 480x800+ | 24bit | 手机、平板 |
| HDMI 屏 | -- | HDMI | 各种 | 24bit | 桌面显示器 |
| E-Ink | SSD1680 | SPI | 各种 | 1bit | 电子书 |

### 11.3 各类接口的特点与选择

| 接口 | 引脚数 | 速度 | 适用场景 |
|------|--------|------|---------|
| I2C | 2 | 100k~1M | 小屏 (<128x64)、低速刷新 |
| SPI (3-wire) | 3 | ~50MHz | 中等屏、快速刷新 |
| 8080 Parallel | 12~20 | ~20MHz | 大屏、极速刷新 |
| MIPI DSI | 4~8 (差分) | ~1GHz | 高分辨率彩色屏 |
| LVDS | 8~10 (差分) | ~600M | 工业/车载大屏 |
| HDMI | 19 | 3.4G+ | 桌面显示器 |

选择建议：128x64 单色屏用 I2C 足够；240x240 彩色屏用 SPI；320x480 以上优先 SPI 或 8080；带 GPU 的 MPU 直接 HDMI/MIPI。

### 11.4 从 SSD1306 到其他控制器的迁移

通用初始化框架：1.上电延时 2.软件复位 3.接口配置 4.面板参数 5.时序参数 6.电源配置 7.Gamma/色彩（彩色屏） 8.显示方向 9.清屏->打开显示

从 SSD1306 换到其他控制器时的关键差异：
| 关注点 | SSD1306 | ILI9341 (TFT) |
|--------|---------|---------------|
| 色深 | 1bit | 16bit (RGB565) |
| 显存大小 | 1KB | 150KB |
| 像素格式 | 1 pixel = 1 bit | 1 pixel = 2 bytes |
| 坐标设置 | page+column | X/Y 起止地址 |
| 帧缓冲 | MCU 内存中 | MCU 内存或控制器 GRAM |

所有屏都能亮的最低初始化序列：reset -> sleep out -> display on。仅此三步（加上正确的接口配置），任何屏幕都能点亮。其余命令都是为了让显示好看。

### 11.5 帧缓冲策略：何时需要、何时不需要

| 场景 | 帧缓冲位置 | 大小 | 原因 |
|------|-----------|------|------|
| SSD1306 128x64 | MCU 内存 | 1KB | 任何 MCU 都能承受 |
| ILI9341 320x240 | 控制器 GRAM | 0KB MCU | MCU 内存不够 (150KB) |
| ILI9341 + STM32H7 | MCU 内存 | 150KB | H7 内存充足 (1MB+) |
| RA8875 + SDRAM | 外部 SDRAM | 外部 | 控制器自带显存 |

经验法则：帧缓冲 < 10% MCU RAM 用全帧缓冲；> 50% 直接写入控制器 GRAM；10%~50% 需评估复杂度。

### 11.6 双缓冲与无撕裂渲染

单缓冲（本项目）：绘制 -> buffer[] -> 发送到屏。128x64 单色屏撕裂不明显，单缓冲足够。
双缓冲：Frame0 后台绘制，Frame1 前台显示，然后交换。渲染时间 < VSYNC 间隔时最佳。
三缓冲：LCD 大屏常用，允许一个帧被跳过，渲染时间接近 VSYNC 时选择。

### 11.7 从单色到彩色的升维

| 维度 | 单色 | 彩色 |
|------|------|------|
| 像素大小 | 1 bit | 16~24 bits |
| 绘点函数 | buf[offset] |= (1<<bit) | buf[offset*2]=color_hi; buf[offset*2+1]=color_lo |
| 填充操作 | memset(buf, 0xFF, size) | 需要循环写 2 字节 |
| Alpha 混合 | 无 (二值) | 支持半透明 |

### 11.8 图形库选型

| 库 | 适用场景 | 优点 | 缺点 |
|-----|---------|------|------|
| 手写 | 128x64 单色、简单 UI | 零开销、完全可控 | 无图形能力 |
| u8g2 | 单色 OLED/LCD | 支持上百种控制器 | 只能单色 |
| LVGL | 彩色屏、复杂 UI | 丰富控件、动画 | Flash/RAM 占用大 |
| emWin | 商用产品 | 专业级 | 需授权 |
| TFT_eSPI | ESP32/ESP8266 | 性能极好 | 仅 ESP 平台 |

本项目选择手写 menu_mgr 而非 LVGL 的原因：LVGL 最低 RAM 约 32KB + 60KB Flash，手写仅 ~3KB Flash + ~60B RAM，且 128x64 单色屏上 LVGL 大部分功能无用。

### 11.9 显示性能优化检查清单

- 接口带宽：I2C 是否用了 Fast Mode？SPI 时钟是否调到最高？
- 传输粒度：是否合并了多条命令到一次传输？
- 脏矩形刷新：是否只更新变化区域而非全屏？
- DMA 传输：大屏 SPI 传输是否用了 DMA？
- 字库缓存：常用字符是否缓存了字模指针？
- 绘图剪裁：是否做了边界检查避免越界写？
- 超时处理：I2C/SPI 操作是否有超时而非死等？

### 11.10 当前项目的可扩展方向

1. 换更大的屏：保持 display_mgr 接口不变，只需替换 ssd1306.* 为新控制器驱动
2. 加更多特效：在 effects[] 函数表中注册新特效函数
3. 接入 LVGL：ssd1306_write_data 改为 lv_disp_flush_cb
4. 支持 WiFi 远程：RK3506 网关目录已预留，可实现无线投屏
5. 多屏管理：display_mgr 支持多个实例，每个管理一块屏

## 十二、常见问题与调试技巧

### 12.1 屏幕完全不亮

| 可能原因 | 检查方法 |
|---------|---------|
| 电荷泵未启用 | 确认初始化序列包含 0x8D, 0x14 |
| 显示未打开 | 确认最后发送了 0xAF |
| I2C 地址错误 | SA0 接 GND->0x3C, 接 VCC->0x3D；用逻辑分析仪抓取 |
| 复位不充分 | 初始化前加 100ms 延时 |
| 电源问题 | 万用表测 VCC 是否为 3.3V |

### 12.2 花屏或显示错乱

| 症状 | 可能原因 |
|------|---------|
| 随机像素闪烁 | 未先清屏，GDDRAM 中有随机数据 |
| 显示上下颠倒 | COM 扫描方向设置反了 (0xC0 <-> 0xC8) |
| 显示左右镜像 | 段重映射设置反了 (0xA0 <-> 0xA1) |
| 文字叠影 | update_screen 前未 memset 清空 buffer |

### 12.3 刷新慢/卡顿

| 症状 | 可能原因 |
|------|---------|
| 每帧超过 50ms | 检查 I2C 是否用了 100kHz 而非 400kHz |
| update_screen 耗时异常 | 每个 page 独立 START/STOP -> 合并命令序列 |
| MCU 主循环卡顿 | 检查是否有阻塞等待，所有 I2C 操作应有超时 |

### 12.4 I2C 总线挂死

症状：屏幕停止更新，MCU 卡在 HAL_I2C_Mem_Write。原因：SDA 被从机意外拉低。解决：使用超时而非 HAL_MAX_DELAY；检测超时后复位 I2C 外设。本项目使用 100ms 超时返回错误码。

### 12.5 调试工具链

| 工具 | 用途 |
|------|------|
| 逻辑分析仪 | 抓取 I2C 波形，验证时序和地址 |
| J-Link/ST-Link | 单步调试，查看 buffer 内容 |
| 串口调试 | 打印显存状态、帧率等 |
| PC 预览 (本项目) | 在 PC 上用 GDI 模拟 OLED，不用烧录即可验证显示效果 |
